# 四、框架规则 → 同花顺数据接口映射

> 上游: [HiThink-Tech/Financial-API](https://github.com/HiThink-Tech/Financial-API)，同花顺金融数据服务。
> Base URL `https://fuyao.aicubes.cn`，认证 Header `X-api-key`，成功判据是 HTTP 200 **且** 响应体 `code == 0`。

## 1. 逐条规则对应到哪个端点

| 框架规则 | 需要的数据 | 端点 | 关键字段 |
|---|---|---|---|
| L0 大盘闸门 M | 宽基指数日线（价 + 量） | `GET /api/a-share-index/prices/historical` | `close_price` `volume` `date_ms` |
| L1 板块目录 | 行业/概念板块清单 | `GET /api/a-share-index/catalog/ths-index-list?tag=industry` | `thscode` `name` |
| L1 板块景气 | 板块指数日线 | `GET /api/a-share-index/prices/historical` | 同上 |
| L1 → L2 传递 | 板块成分股 | `GET /api/a-share-index/constituents/ths-stock-list` | `thscode` `ticker` `name` |
| C 当季业绩 | 季度利润表（累计口径） | `GET /api/a-share/financials/income-statements?period=quarterly` | `parent_holder_net_profit` `operating_income` `basic_eps` `period_end_ms` `report_date_ms` |
| A 年度业绩 | 年度利润表 | 同上，`period=annual` | 同上 |
| A 的 ROE | 年度资产负债表 | `GET /api/a-share/financials/balance-sheets?period=annual` | `holder_equity_total` |
| N 股价新高 | 个股前复权日线 | `GET /api/a-share/prices/historical?adjust=forward` | `high_price` `close_price` |
| S 量能 | 个股日线成交量与成交额 | 同上 | `volume` `turnover` |
| L 相对强度 | 个股日线（全池） | 同上 | `close_price` |
| I 机构认同（代理） | 龙虎榜机构榜 | `GET /api/a-share/special-data/dragon-tiger-list?board_type=org` | `org_net_value` `thscode` |
| L3 止损/买点 | 个股日线 | 同上 | `close_price` `volume` |
| 辅助：估值参考 | PE/PB/PS/PCF 快照 | `GET /api/a-share/valuations/snapshot` | `pe_ttm` `pb_mrq` |
| 辅助：代码消歧 | 名称→`thscode` | `GET /api/meta/tickers/search` | `thscode` |

估值端点在本框架中**只用于事后记录，不作为筛选条件**。欧奈尔第 20 章第 8 条明确说不按市盈率买股，且统计显示表现最佳股票启动时的市盈率高于市场平均。

## 2. 框架需要但接口不提供的数据

诚实列出缺口比假装完整重要。

| 框架/原书要求 | 接口是否提供 | 本项目的处理 |
|---|---|---|
| 机构持股家数及其季度变化（I 的原义） | **否** | 用龙虎榜 `org_net_value` + 日均成交额做代理，I 权重降到六因子最低的 10 分，并在输出里标注 |
| 基金业绩评级（判断机构"质量"） | 否（基金端点只覆盖基金自身） | 不实现 |
| 分析师一致预期（下一年 EPS ≥25%） | 否 | 不实现，A 因子只用已披露的历史年度 |
| 管理层持股比例、股票回购公告 | 否 | 不实现，S 因子只保留量能和流动性 |
| 分钟 K / tick | 否（上游明示不在公开范围） | 不实现，框架全部基于日线 |
| 历史成分股（调入调出序列） | 否，成分股端点只给当前成分 | 回测会有幸存者偏差，文档中标注 |
| 公告原文（定期报告、招股书 PDF） | **否**（上游 README 注明公告与研报 "not publicly available"） | 改从巨潮公开查询端点附 PDF 外链（§6），仅作阅读入口 |
| ST 标记 | 仅涨停池等特色端点带 `is_st` | `StockInput.is_st` 需调用方自行填充 |

## 3. 三个必须遵守的调用纪律

### 3.1 错误码分类，不要无脑重试

契约把错误码分成两类，`jingshui/client.py` 按此实现：

- `1001/1002/1003/1004/2001/2003/3001/3004` 是**调用方可修复**的，改参数，不重试。
- `3002`（数据尚未准备）也不重试，保留 `request_id` 稍后再查，**不得补零或用模拟数据顶替**。
- `4001`（限流）和 `5001/5002/5003`（服务端异常）以及网络错误，指数退避，最多 3 次。

### 3.2 `null` 不是 0

`null` 表示未披露或上游无值。全项目一律用 `None` 表示，不补零、不取绝对值。估值指标允许为负（亏损或负现金流），不能据此判定数据错误。

### 3.3 大结果落盘

全市场、多标的、多年数据必须写文件，只在终端报告路径、行数和摘要。`jingshui/pipeline.py` 的 `Cache` 和 `run()` 都遵守这一点：板块目录、成分股、日线全部缓存到 `.cache/jingshui/`，扫描结果写到 `output/`。

## 4. 参数上的几个坑

| 坑 | 说明 |
|---|---|
| 财务报表的两种模式互斥 | `limit` 与 `start`+`end` 不能同时传，否则 `code=1004`；只传 `start` 或只传 `end` 也是 `1004` |
| 财务指标端点的 `report` | 格式是 `YYYY-[1-4]`（如 `2025-1`），**不是日期、不是时间戳** |
| `abilities` 是数组不是对象 | 必须 `for ab in abilities: ab["ability"]`，不能 `abilities["growth"]` |
| 指数没有复权 | 指数行情端点不接受 `adjust` 参数 |
| 指数快照不支持全市场 | 必须显式传 `thscodes` |
| 历史 K 线单标的 | `thscode` 不接受逗号，多标的要分多次请求 |
| 区间跨度上限 | 日线区间 >10 年返回 `code=1003` |
| 估值快照上限按原始 token 计 | 先查 100 个上限再去重，101 个重复代码仍然超限 |
| 龙虎榜省略 `date` ≠ 今天 | 省略时取最新可用交易日；显式日期必须是最近一年内的交易日 |

## 5. 备用数据源 (`--provider free`)

同花顺接口有配额，撞限流时可切到零鉴权的公开接口。取数分工参考
[simonlin1212/a-stock-data](https://github.com/simonlin1212/a-stock-data)：

| 数据 | 源 | 端点 |
|---|---|---|
| 个股/宽基指数日线（前复权） | 腾讯 | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` |
| 财报三表（累计口径） | 新浪 | `quotes.sina.cn/.../CompanyFinanceService.getFinanceReport2022` |
| 板块目录与成分 | 东财 | `push2.eastmoney.com/api/qt/clist/get` |
| 板块日线 | 东财 | `push2his.eastmoney.com/api/qt/stock/kline/get` |

**东财必须串行限流**。该项目记录了一手封禁案例：不走限流的并发脚本 1 小时发出
45000+ 请求，`push2` 全系列被 IP 级封禁 20 小时以上。因此本项目对 `eastmoney.com`
强制串行、默认间隔 1.2 秒，撞到 403/429 自动翻倍。腾讯和新浪不封 IP，只在高频下限流。

三处与同花顺不等价的地方（机构净额缺失、披露日推算、成交额估算）见 README 的
「free 数据源的三处实质差异」。

## 6. 公告原文（定期报告 / 招股书，巨潮公开端点）

同花顺金融数据服务不提供公告原文，因此展示列表个股附巨潮资讯（www.cninfo.com.cn）
「最新定期报告 / 上市招股书」PDF 外链，实现见 `jingshui/cninfo.py`。零鉴权、与主/备
数据源无关；只产出链接，不下载 PDF 入库。

流程：orgId 查询 → 公告查询 → `static.cninfo.com.cn` 直链。

| 步骤 | 端点 | 关键参数 |
|---|---|---|
| orgId | `POST /new/information/topSearch/query` | `keyWord=六位代码`，取返回中 `code` 匹配项的 `orgId`（`gssz…`/`gssh…`/`gfbj…` 前缀） |
| 定期报告 | `POST /new/hisAnnouncement/query` | `category=category_ndbg_szsh;category_bndbg_szsh;category_yjdbg_szsh;category_sjdbg_szsh;`（年报/半年报/一季报/三季报合并），已按披露时间倒序，取第一条正文（排除「摘要」「英文版」） |
| 招股书 | 同上接口 | `searchkey=招股说明书`，取第一条（排除「摘要」「提示性公告」）；北交所直连上市公司标题即「招股说明书」 |
| PDF 直链 | `https://static.cninfo.com.cn/` + 返回的 `adjunctUrl` | 约 2000 年前的极老公告可能是 `.html` 且个别已失效，属数据源边界，页面显示原链接 |

公告查询共同参数：`column`/`plate` 按交易所——深 `column=szse`、沪 `column=sse&plate=sh`、
北 `column=bj`；`stock="{六位代码},{orgId}"`、`tabName=fulltext`、`isHLtitle=false`
（标题不带 `<em>` 高亮标签）、`sortName/sortType/seDate` 留空；`pageSize` 定期报告 30、
招股书 10。请求带浏览器 UA 与 `Referer: https://www.cninfo.com.cn/`，串行、间隔 ≥0.5s，
403/429/5xx/非 JSON 退避重试最多 3 次。

缓存 `.cache/jingshui/cninfo/{thscode}.json`：`orgId` 永久缓存；招股书命中后永久；
定期报告按 TTL 刷新——披露旺季（4/8/10 月）1 天、其余 5 天，`config.yaml` 的 `docs`
段（`enabled/interval/cache_days/cache_days_season`）可整体关闭。链接始终取"当前最新"，
补跑历史时不做时点还原（纯阅读用途）。单只失败只记日志、不写缓存；全部失败时页面
警告并省略链接，不影响主流程。

> 巨潮官方开放平台 webapi.cninfo.com.cn 另有公告数据集（如 `p_info3085t` 最新深沪北
> 上市公司 PDF 公告），但需注册申请授权码，本项目未采用；本文档所述公开查询端点与
> 官网同源、零鉴权。

## 7. API Key 处理

- 只从环境变量 `HITHINK_FINANCE_API_KEY` 或用户级 `~/.config/hithink-finance/credentials.env` 读取。
- **绝不**写入代码、日志、异常信息、公开配置或 Git 提交。
- 通过 Header 传递，不放进 query string（`tests/test_client.py` 有专门的用例守住这一点）。
- 申请地址：<https://fuyao.aicubes.cn/admin/>
